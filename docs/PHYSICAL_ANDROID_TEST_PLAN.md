# HomeBuddy — ручне тестування фізичного Android-пристрою

Статус усіх сценаріїв нижче: **НЕ ВИКОНАНО НА ФІЗИЧНОМУ ТЕЛЕФОНІ**.
Автотести й скриншоти емулятора не змінюють цей статус. Заповнювати результат
окремо для кожного телефону та APK: PASS / FAIL / BLOCKED, фактичний результат,
час події, скриншот або запис екрана. Не використовувати особисті дані у доказах.

## Паспорт прогону

- Дата, тестувальник, Git commit, SHA-256 APK, версія Flutter.
- Виробник/модель, Android/API, прошивка, launcher і його версія.
- Часовий пояс, мова системи, формат часу, battery optimization, DND.
- Назва/версія TTS engine, установлені українські голоси, speech recognizer,
  застосунок камери, наявність мережі, тип навушників.
- Бажана матриця: Android 12/API 31 або 32, Android 13+/API 33+,
  актуальний Android; Pixel/стандартний launcher і щонайменше одна OEM-прошивка.

## Підготовка й оновлення без втрати даних

1. На окремому тестовому телефоні ввімкнути USB debugging, авторизувати комп'ютер.
   `adb devices -l` має показати пристрій як `device`.
2. APK: `build/app/outputs/flutter-apk/app-debug.apk`. Передати/встановити через
   `adb -s SERIAL install -r /ABSOLUTE/PATH/app-debug.apk`.
3. Для перевірки оновлення спочатку встановити попередній APK із тим самим
   applicationId `app.homebuddy.home_buddy` та тим самим debug signing key.
   Створити 3 справи (звичайна, виконана, з фото та майбутнім нагадуванням),
   налаштувати змінний графік і mute. Зберегти назви й часові значення в протоколі.
4. Встановити новий APK через `install -r`, без uninstall і без Clear storage.
   Помилка підпису — BLOCKED: потрібен APK із попереднім ключем. Не видаляти
   встановлений застосунок для обходу помилки, якщо треба перевірити збереження.
5. Перевірити всі справи, фото, виконаний стан, графік і mute після оновлення,
   закриття застосунку, повторного відкриття та перезапуску телефону.
6. Окремо перевірити чисте встановлення на пристрої/профілі без потрібних даних.
   На старті немає примусової реєстрації або запитів необов'язкових дозволів.

## Введення, дозволи, камера

| ID | Дії | Очікуваний результат |
| --- | --- | --- |
| UX-01 | Нова справа → ввести назву → Done на клавіатурі | Одна справа збережена; категорія «Дім», фото й нагадування необов'язкові; повернення додому без додаткових питань. |
| UX-02 | Порожня назва/пробіли; потім 120 символів; швидко натиснути Save двічі | Порожню назву відхилено; довжина обмежена; немає дублів. |
| MIC-01 | «Продиктувати» → дозволити мікрофон → сказати українську назву → зупинити → виправити текст → Save | Текст українською редагується; після збереження мікрофон не працює. |
| MIC-02 | Відмовити мікрофону, повторити після постійної відмови | Зрозумілий текст про дозвіл/налаштування; ручне введення та Save працюють; немає циклу запитів. |
| MIC-03 | Відкликати дозвіл у системі; вимкнути speech service / видалити українську модель; повторити без мережі | Пояснення недоступності, без зависання й втрати введеного тексту. Offline-можливість фіксується як властивість системного recognizer. |
| MIC-04 | Під час диктування Home, блокування, Back, зміна екрана, Save | Запис зупиняється; пізній результат не перезаписує збережену назву; після повернення запис не починається сам. |
| CAM-01 | «Фото несправності» → зробити фото → підтвердити → Save → відкрити фото справи | Фото є після закриття/оновлення застосунку; файл збережений у приватному сховищі. |
| CAM-02 | Відкрити камеру → Back; потім відмовити дозволу всередині системної камери / вимкнути камеру | Скасування тихе; помилка пояснює можливість зберегти без фото; назва не втрачається. |
| CAM-03 | На тестовому телефоні ввімкнути «Не зберігати дії», зробити фото, повернутися | Фото відновлюється через lost-data recovery; немає падіння. Після тесту повернути системне налаштування. |
| CAM-04 | Зберегти фото → видалити справу; перевірити відсутність несподіваних permission prompts | Справа зникає, приватне вкладення прибирається. Фото в галереї, якщо його створювала зовнішня камера, не видаляється застосунком. |

HomeBuddy використовує зовнішній camera intent через image_picker, а не власний
camera preview. Тому власний `CAMERA` і дозвіл читання всієї галереї не потрібні;
системна камера може запитувати власні дозволи. `RECORD_AUDIO` запитується тільки
для голосового введення. На Android 13+ `POST_NOTIFICATIONS` запитується для
першого нагадування; на старіших Android перевірити також системний перемикач
сповіщень і канал «Нагадування про справи».

## Сповіщення, графік і перезапуск

Перед кожним сценарієм записати поточний часовий пояс, бажаний час, очікуваний
час за графіком, фактичний час доставки та стан DND/battery. Для короткого тесту
обрати вихідний день, дозволене вікно навколо поточного часу й сон поза ним.
Нагадування — inexactAllowWhileIdle: Android може затримати доставку. Відсутню
доставку не позначати PASS; перевірити дозволи, канал, Doze й OEM-обмеження.

| ID | Дії | Очікуваний результат |
| --- | --- | --- |
| NOT-01 | Додати нагадування на кілька хвилин уперед → Allow | Рівно одне локальне сповіщення з назвою справи; зафіксувати затримку ОС. |
| NOT-02 | Deny сповіщення / вимкнути весь застосунок або канал у системі | Справу збережено; зрозуміле пояснення, що сповіщення недоступне; ручне використання працює. |
| NOT-03 | Створити нагадування → позначити справу виконаною до доставки | Після очікуваного часу сповіщення не з'являється. Повторити після перезапуску телефону. |
| NOT-04 | Створити нагадування → видалити справу до доставки | Немає сповіщення, включно після reboot/update. При помилці скасування справа залишається, є повідомлення для повтору. |
| NOT-05 | Виконати → повернути у невиконані перед майбутнім часом | Нагадування відновлено один раз; після повторного виконання скасовано. |
| NOT-06 | Запланувати → закрити свайпом із Recents → дочекатися; окремо reboot і unlock | Нагадування переживає звичайне закриття та перезапуск через boot receiver. Android Force stop — окремий системний випадок: доставка може бути зупинена до ручного відкриття. |
| NOT-07 | Вимкнути мережу після планування | Локальне сповіщення не залежить від інтернету. |
| SCH-01 | Пн–Пт 09:00–17:00, дорога 30 хв, відпочинок 60 хв, сон 23:00–07:00, дозволено 08:00–22:00. Пн 02.11.2026 побажати 10:00 | Запланований час 18:30. На вихідний 01.11.2026 о 10:00 — 10:00. |
| SCH-02 | Цикл 2/2 від 01.11.2026; робота 22:00–06:00, дорога 30, відпочинок 60, сон 08:00–16:00, дозволено цілу добу (однакові межі). Побажати 02.11 о 06:30 та окремо 08:30 | Відповідно 07:30 і 16:00; нічна зміна попереднього календарного дня врахована. |
| SCH-03 | Нагадування вже перенесено з минулого бажаного часу на майбутній → змінити графік і Save | Очікуване нагадування не втрачається й не дублюється; виконані/видалені не відновлюються. |
| SCH-04 | Межі вікна через північ; час точно на початку/кінці; немає жодного вільного слота | Початок включено, кінець виключено; некоректний/неможливий графік дає пояснення без зависання. |
| SCH-05 | На тестовому телефоні змінити часовий пояс/дату, перейти через DST, перезапустити | Записати фактичний час; не вважати автоматичне слідування «настінному часу» підтвердженим. Поточні задачі зберігають абсолютний timestamp. Перед поверненням до звичайного тесту відновити системний час. |

## Завершення та критерій готовності

- Заповнити кожен рядок; BLOCKED не прирівнювати до PASS.
- Не повинно бути втрати задач/фото після update/reboot, crash, зайвого запису
  мікрофона, звуку після Stop/mute/navigation/lock, або сповіщень завершених справ.
- Перевірити журнал помилок через `adb -s SERIAL logcat`; не публікувати приватні
  дані журналу. Для дефекту вказати мінімальні кроки, очікуване/фактичне, APK hash.
- Передати: заповнений протокол, скриншоти/відео, модель/ОС, список FAIL/BLOCKED.
